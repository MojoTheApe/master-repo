# Task lifecycle presentation

Keep five read-only categories: Backlog, In Progress, Review, Delivery and Done.
They show recorded position, not authority to start, approve, integrate or publish.
Each project keeps its actual native status keys and selected workflow/controls.

Review contains unfinished review: waiting for a genuine handoff, awaiting a
Reviewer, currently reviewed, or needing clarification. Existing genuine approved
waiting-route work appears in Delivery as **Ready for integration**. Its stored
`approved` key, source review and task/PR history are preserved. A label alone or
missing/contradictory observation is not trusted ready work.

Within Delivery, ready sources wait for their permitted integration. **Integrating**
describes the held composition/Stage/main operation. **Awaiting Release** requires
actual accepted main work with a genuinely pending required publication;
**Releasing** requires the compatible Tracker's qualified current observation.
Done requires the project's actual whole-scope completion. A proven process-only
update follows its own delivery and does not wait for a consumer installer.

Queue size counts tasks. Reserved capacity counts actual owned slots. Confirmed
activity describes actual current executor reports. A batch can contain several
tasks in one integration reservation; a held reservation alone is not running
work. Keep these facts separate in counts, navigation and descriptions.

Waiting age uses the timestamp of the actual current native source approval.
Missing, malformed or mismatched evidence remains unknown. Never infer it from
the Issue's last edit, source creation, an old approval or active-work durations.
Saved snapshots retain their saved age rather than claiming current observations.
Waiting tasks remain unfinished work; monitor accumulation and finish existing
work through the selected gates before expanding work indefinitely. This prose
does not introduce new limits, queue ordering, automatic admission or a scheduler.

Explicit pause retains the current category, including approved work in Delivery,
and preserves source/history, frozen batches, Stage and real product requests.
Resume follows [owned pause rules](task-pause.md) with fresh actual authority.
Lost confirmation never releases a slot. Existing native stale-source/scope/main
checks and supported return/re-review paths remain mandatory. The UI never
manufactures current approval or forces a task transition to reconcile a display.

Task Tracker owns the central rendering and executable semantics. Master owns
this common rule and its guidance. Publish matching compatible support through
the maintained exact-source path; consumer adoption remains a separate operation.

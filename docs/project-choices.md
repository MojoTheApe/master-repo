## Choose independent properties

Descriptor3 records repository `role`, delivery `profile`, required `completion`,
the explicit `workflow.execution.route`, Stage and actual capacity separately.
Repository role describes the work; it does not grant a route, relax checks,
change the completion target or define a task navigation category.

| Property | Selection |
| --- | --- |
| Role | application, shared-tooling-library, application-data, release-storage, knowledge or research |
| Integration | direct or batch in explicit execution4 |
| Stage | Explicit on/off, with the actual permanent branch and verification target |
| Work capacity | Actual selected true integer1..16 |
| Source-review capacity | Actual selected true integer1..5 |
| Batch members | Actual selected true integer1..5 for batch; absent for direct |
| Integration capacity | One shared reservation; no independent configurable limit |
| Delivery | Existing profile, actual project target and required completion |

Modern execution selects the known task-context2 and completion-policy1 bundle.
It does not infer activation from files, a newer skill or a role. Existing
descriptor1/2 and execution1/2/3 retain their selected semantics. Ordinary upgrade
preserves actual choices and absence rather than silently converting a project.

## Review and integrate the actual source

The pinned Tracker guide owns exact commands, subject fields and transitions.
Master consumes that selected guide and exact PR template instead of maintaining
a second command contract.

Direct engineering keeps a real Issue, actual Worker, independent source review
and full applicable checks. Stage off uses working source to main. Stage on uses
that same single source through permanent Stage and then main with exact Stage
verification. It creates no Approved waiting pool and no synthetic batch.

The actual source Reviewer retains its source lane and owns the linked single
integration reservation. A second mandatory Reviewer run is unnecessary for the
same independently reviewed unchanged source. Batch still uses real Approved
members, a frozen composition and its distinct integration Reviewer; a one-member
batch remains a batch. Both paths serialize against existing batch/intake/Stage,
process integration, maintenance and other real admission barriers.

Main advancement requires actual independent compatibility review of unchanged
source and relevant semantics. Disjoint paths alone do not establish safety.
Conflicts or required implementation return to the genuine author claim; changed
content needs fresh applicable evidence and independent review.

After actual main merge, retain the source Reviewer and reservation while the
maintained finalizer records the exact accepted-scope/main receipt and reconciles
the real task status. Archive/release only afterward. Crashes after merge, receipt,
status or release reconcile that exact operation; absent ownership is not proof
of completion. Pending required package/production/publication remains unfinished
after a legitimately released source reservation.

## Ordinary knowledge capture

Role and Markdown extension alone never authorize a no-Issue path. The actual
official main must already contain the identical explicitly selected/adopted
knowledge-capture policy, with project-owned note roots and the real approved
semantic mandate. New documentation, a preset or the note itself does not enable
or broaden that mandate.

The canonical classifier reads complete immutable trees, regular modes and
bounded UTF-8 blobs. Initial formats are `.md` and `.txt` additions/modifications
under the selected roots. Deletion/move/rename, executable/binary/oversized or
truncated content, symlink/submodule, unsafe paths/collisions and mixed changes
use the normal tracked engineering route. AGENTS, CLAUDE, SKILL, README, index,
structure, configuration, workflow and automation are governance regardless of
extension or directory. Keep the existing narrow process-instructions exception
on its own adopted real-task contract.

Actual semantic assessment and independent review must attest that the complete
diff stays within the already approved mandate and changes no consumed rules,
structure, configuration, automation or delivery. Mechanical binding records
that assessment; it cannot prove prose harmless or create a new owner instruction.
Outside-mandate work needs a real engineering task or an authorized reviewed
policy change first.

A capture operation has one genuine public operation identity and source PR; it
consumes the normal Worker, source-review and integration pools. It creates no
Issue, alias, release member or task dependency. Grouped ordinary notes may share
one operation. Actual PR intent/unknown-response recovery, owner independence,
full checks, Stage choice and native protection remain mandatory. Public operation
identity is not a private claim token or permission to resume another owner.

Even in a batch-selected knowledge project, an explicitly selected eligible
capture uses the serialized single-source exception only after real batch/Stage
work releases. Governance work continues through its selected tracked route.
Initial capture supports reviewed-merge delivery; a runtime/package obligation
cannot be silently bypassed. Authored skills/rules and a later verified generated
skill-mirror exception remain different contracts.

## Upgrade, activation and recovery

Use a genuine pristine old template base and compare old/new/local. Preserve
project-owned system/runtime files, identity, IDs/history, actual limits, Stage,
targets, optional policy absence and local safeguards. Resolve ambiguous overlaps
in an owned project PR; never replace the recorded old base with local bytes just
to make an upgrade pass.

An explicitly requested modern choice is reviewed configuration, not durable
activation. Publish compatible actual readers/writers before owned idle migration
of the execution4/context2/completion1 bundle. Initial outer7 retains actual base5
or base6; retry6 stays inside it with its original anchor, budgets, causes and
uncertain dispatch intents intact. Busy owners, pending Stage/delivery/intake,
unconsumed approvals or unknown external effects must drain under their own
supported transitions. No timeout clears them.

Capture policy remains absent unless explicitly selected. It may be adopted in
that known bundle only with its actual mandate and real reader support. No CI
evidence/retry policy, producer refresh or resource registration is implied.
When canonical producer bytes change, preserve old consumer truth and refresh
its actual workflow/blob/policy in its separately owned project change; old
metadata cannot certify the new producer or unsupported capture reuse/retry.

After outer7 adoption, an old reader/writer must refuse before mutation. Recovery
retains the fence/history and uses a known compatible reader/writer under owned
maintenance. It never strips wrappers or restores a preprotocol backup to make
an old client run. Standard/skill publication itself changes no consumer state.

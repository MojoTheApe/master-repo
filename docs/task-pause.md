# Pause retains the current workflow phase

MR-70 pairs the global rule with Tracker TT-179. The compatible engine owns the
actual commands; follow its selected local guide and TASK_PAUSE.md. This rule
applies to every installation/deployment profile. It is part of the process,
not a product installer change. Publication and consumer activation are separate.

A confirmed stopped executor is explicitly checkpointed through `pause stop`,
using its actual role/session/claim or recorded Coordinator, `--stopped` and a
durable handoff report. The owner's direct confirmation of stop is sufficient;
silence, time elapsed or an unavailable host is not. Never impersonate a prior
run, invent a copied worktree, or edit ownership state manually.

Paused replaces the displayed normal status inside the saved category: In Review
becomes Paused inside Review, implementation stays In Progress, and admitted
Stage/frozen integration stays Delivery. Keep native task phase, source PR,
branch/work location, all history and real blockers/dependencies. Only the
stopped executor's actual slot is released. A combined Reviewer pause retains its
Coordinator reservation; frozen integration blocks conflicting admission even
when an executor slot is free. Actual pending product requests remain unchanged.

Resume explicitly checks genuine capacity, current task scope/phase,
source/linkage/branch/route, main, dependencies and role independence. It returns
fresh authority before restoring active presentation. Workers preserve the saved
branch/worktree. A frozen Coordinator resumes with a genuinely new session while
retaining immutable batch composition/identity, before its combined Reviewer.
No slot, a blocker or changed evidence leaves the task paused with a reason.
Old review evidence remains history; new independent review is required before
new admission. Unsafe operations already committing/finalizing main use their
existing recovery and refuse a premature pause.

Only actual owner-bound activity reports count as running. A missing report for
five minutes freezes confirmed time and displays Connection lost after prior
confirmation. Never-observed work stays Activity unconfirmed. Neither frees a
claim, changes the native phase or establishes a stopped process. A stopped
activity report alone is not a slot release. The read-only UI cannot restart work.

Before first use, verify the published compatible engine and complete helper
closure, installed service reader and every actual writer/adapter/recorder.
Retain exact revisions and real readiness evidence in the maintenance report.
Reserve owned maintenance, drain actual owners including legacy timer bindings,
then preview/apply `pause activate` only at genuine idleness. Resume that same
owned maintenance. Outer8 retains the complete incumbent1..7 guard bundle and
causes older readers to refuse. Never remove/downgrade it after paused history.
No new optional policy, daemon, scheduler, consumer product publication or live
activation follows from an upstream release, export, skill update or pin edit.

Existing consumers retain their pinned semantics until separately reviewed
adoption. Do not rename the older Todo-moving stop/review-return operation as
phase-preserving Pause. Preserve their real permissions, pending work, configured
capacities, Stage, installation and operational controls throughout adoption.

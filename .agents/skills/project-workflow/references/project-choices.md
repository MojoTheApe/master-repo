# Explicit project choices and single-source work

Use this reference only when the actual pinned project explicitly selects the
compatible descriptor3/execution4 contract. A newer installed skill is not that
selection or durable activation. Older projects keep their checked-in guide and
own schema1/2/3/legacy behavior.

Role describes application, tooling/library, data, release storage, knowledge or
research work. It grants no route, capacity, completion, capture mandate or task
category. Keep delivery profile, actual target, required completion, route and
Stage independent. New-project presets expose conservative choices; an existing
project's limits and targets do not change because a newer preset recommends
different values. Resource registration requires its actual producer contract.

Read the exact generated local Tracker guide. Tracker owns the execution4 parser,
typed task/capture subjects, command fields, PR template, complete-diff classifier,
owned transitions and portable admission. Do not invent command syntax from this
reference or make a second policy definition in a consumer.

A directly reviewed engineering source has a genuine Issue, Worker, independent
source Reviewer and full applicable evidence. It does not enter Approved or a
synthetic batch. With Stage off it reaches main; with Stage on it retains that
same subject through actual Stage verification and promotion to main. The real
source Reviewer keeps its lane and the linked integration reservation through
the ordered main receipt, task-status reconciliation and archive/release. A
stopped owner or ambiguous write uses the exact owned recovery, never timeout.

Batch retains real Approved task members, frozen composition and a distinct
integration Reviewer. A singleton batch is still a batch. Both routes serialize
against current integration/Stage/intake/process work and maintenance. A free
number does not authorize a claim; current ownership, scope, checks and CAS do.
Main changes require relevant independent compatibility assessment; disjoint
paths alone do not prove safety. Author fixes require a genuine author claim.

Ordinary notes have no Issue only under the identical already adopted explicit
knowledge-capture policy and actual approved semantic mandate. Complete trees,
regular file modes and bounded UTF-8 `.md`/`.txt` blobs are necessary, not authority.
Governance names, structure, rules, configuration, automation, mixed/unsafe diffs
or a newly introduced/broadened policy use tracked engineering. Actual semantic
assessment/review is an attestation; the parser cannot prove prose harmless.

Capture uses one real operation and PR, actual ownership, independent review,
full checks, current protection and the project's Stage choice. It consumes the
normal pools without creating a fake Issue, dependency, release member or timer
task. Public operation ID never substitutes for a secret claim. Ambiguous PR POST
or finalization retains its barrier/history until exact-operation reconciliation.
Even a batch-selected project's eligible capture waits for current batch/Stage
ownership; it cannot turn a governance change into an exempt note.

Modern selection requires task-context2 and completion-policy1. Source/config
publication is separate from actual compatible-reader support and owned idle
outer7 migration. Preserve retry6's anchor, budgets, unresolved causes and unknown
dispatch through unrelated task/capture work. Keep capture/CI/retry selections
absent unless explicitly requested. Do not drain another owner or strip a state
fence for rollback.

Required production, package installation or publication remains unfinished at
source merge; a note receipt, role or fast check cannot supply missing delivery.
Initial capture cannot waive a runtime/package obligation. Authored skill/rule
work retains its actual task; a verified generated mirror exception belongs to
its separate exact-copy publication contract.

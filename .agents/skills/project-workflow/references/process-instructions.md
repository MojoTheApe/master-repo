# Instruction-only route

Process and product delivery are separate in every profile. This schema1 route
is one bounded implementation of that rule, not permission to classify arbitrary
scripts, configuration or CI as instructions. Compatible canonical shared-support
upgrades need their actual published proof support and retain ordinary admission.
Preserve explicit product publication and existing authorized delivery requests.
Do not claim a consumer adopted new executable support from an installed skill.

The separate isolated_verification1 capability can finish a bounded added manual
verification workflow after ordinary main admission and actual verification. Use
the pinned guide's process-support proof and supplemental independent whole-scope
assessment, including indirect product/build/credential effects. Syntax is only
eligibility. Require the exact successful official workflow_dispatch attempt and
all expected jobs at the admitted main merge, original review/scope/acceptance and
no product publication obligation. Preview the evidence before apply; retain the
pending receipt history and actual new assessor identity. This neither broadens
the instruction route below nor acquires or rewrites another developer's review.

Use only when the pinned engine supports it and `delivery.json`
`workflow.process_instructions` exactly matches Tracker's top-level
`process_instructions`. Absence keeps the old route. Updating this skill does not
adopt an exception.

The complete immutable diff must contain only regular AGENTS.md, CLAUDE.md or
Markdown under docs/repository. Renames require both paths to qualify. Unknown,
missing, truncated, symlink, mixed, system/runtime, configuration, automation or
application changes cannot authorize the exception. Rely on the pinned portable
classifier and admission checks; an Issue label or author's description is not proof.

Create/claim one real task and preserve its actual author and handoff. Adopted
execution policies require the genuine independent review lane; legacy projects
keep their existing slot and independent attestation without unsupported execution
commands. Review current head/base/tree/full scope.
The source PR targets main and needs its explicit instruction checks. Use
`record-review`, `check-pr`, `check-merge` immediately before merge and the normal
reviewed-complete `merged` handoff, with only syntax supported by the pinned guide.
In execution v2, keep the review lane through main completion; do not call batch
approval/intake or manufacture Stage or package evidence for this source.

Admission waits until any reserved integration or unpromoted stage candidate is
finished/reconciled. Main cannot move beneath a held batch. Before later staged
work, obtain fresh applicable approvals against current main. Use the pinned
Tracker's read-only baseline proof when stage lags solely by a complete eligible
delta and retained verified process merge receipts/first-parent chain. The new
source/batch starts from current main. Missing receipts or any other divergence
needs the existing claimed reconciliation procedure; never reset/force-update
stage, drop work or change another owner's branch.

Only the fully reviewed instruction outcome completes at admitted main inclusion.
Do not finish a broader parent with missing application/runtime criteria. A mixed
or application/build change retains the normal project integration and delivery
requirements. The configuration/helpers/CI adoption itself follows the old route;
verify actual opt-in before using the exception.

# Verification and coordinated upgrades

When the adopted pin explicitly mirrors `workflow.ci_retry` with
`ci_retry_policy`, read its exact generated CI_RETRY.md before diagnosis or a
native rerun. Compatible published readers/all writers and owned durable
activation precede live use. Use the persisted operator-attested diagnosis and
reviewed verification-only plan, never a bare transient flag or startup_failure
label. A privileged authenticated principal does not prove the human owner
personally reviewed the evidence. Unknown, product, permanent configuration and
billing/access/quota causes do not automatically retry.

If the pin supports a specific-human-instruction grant, follow its separate
operator-attestation procedure and bind the actual message/source/time/action to
the current native identity, episode and named cause. General permission to
continue working is insufficient. Such a grant is single-use, consumes remaining
budget and leaves the cause unresolved; it cannot clear uncertain dispatch or
authorize product operations. State may be public: keep raw evidence and private
instruction references outside Git and retain only allowed facts and digests.

Retain consumed budget, unresolved causes and reservations across sessions, run
IDs, empty commits and cause/plan renaming. Only the fresh dispatch-barrier CAS
winner sends once; an ambiguous CAS/POST or crash keeps budget held for supported
GET-only reconciliation. Timeout, an empty response or an unattributed external
attempt cannot free an uncertain own request. Direct human Actions access is
outside this lock. Native rerun keeps the original SHA/ref/triggering privileges;
a real fixed head needs new-candidate verification. Partial retry requires the
adopted gate's real original-job/dependent proof, otherwise a supported bounded
full attempt or stop. Retry permission never grants deployment/release permission.

Use an on-demand read-only human/JSON report with versioned saved observations
when supplied by the pin. Count actual intervals separately from carried-forward
attempt rows and keep unresolved coverage explicit. Creation cohorts differ from
execution periods; bounded lookback can miss older reruns. Preserve observed,
inferred and unknown reasons, unknown billing and separate current storage.
Interval-minute estimates are not invoices or savings. Compare ordinary workloads
with the same report method and report pending measurement gaps without scheduling
unrequested monitoring or paid demonstrations.

When the adopted pin supplies `docs/portable-contract.md`, follow its exact
generated contract and source-pair gate. Tracker authors the portable frontend,
fixed layout helpers and canonical CI-policy validator; Master consumes their
verified bytes and its own trusted structural snapshot. Do not hand-edit generated
copies, trust a rehashed consumer manifest or introduce a second technical policy.
Public CI uses the exported closure and its own repository read token; author
operations still use the exact private engine in an authorized environment.
Refreshing source artifacts, passing a provisional peer check and publishing a
clean final pair are distinct facts. Consumer adoption remains separately scoped.

Where the pin supplies CI_REUSE.md and matching `workflow.ci_evidence` /
`ci_evidence_policy`, use its maintained plan/missing-job/final-gate recipe.
Explicit protocol 2 supports retained exact merged-main proof; old protocols keep
their context limits. Preserve native job/platform names, real producer/attempt
provenance and actual delivery. Run unsupported or missing coverage fresh.
On CI use the generated portable `scripts/tracker_ci_gate.py plan|gate` entry
point with the same-repository read token; it needs no private engine checkout.
Author CAS collection still uses the authenticated exact pinned full client.
Supported final `check-merge` includes linkage; retain early link feedback without
an immediately duplicated `check-pr` admission step. Keep old pins' commands.

Follow the adopted verification policy and actual product commands. Select the
cheapest meaningful check for changed risk, then all required combined-candidate
and actual delivery checks. Unknown/mixed scope keeps full applicable checks;
test counts alone do not justify removal or a different product stack.

Where the adopted pin supplies `docs/verification-submission.md`, keep the real
project fast/full plan and distinct check names. Group related local corrections
on the same owned task branch while retaining useful early hosted feedback and
checkpoints; impose no arbitrary waiting interval. Ready handoff/admission and
unknown/mixed changes require full applicable coverage. Record why a new heavy
run is needed and its actual candidate/native run; historical inferred reasons
remain inferred. A fast result, renamed plan or instruction-only skip cannot
satisfy missing full coverage or refresh an exhausted retry budget.

Read author evidence before repeating it. Preserve the existing adopted bounded
collector's proof rules, including older exact-tree/merged-PR reuse; a newer skill
does not add environment requirements or force reruns of valid old-pin evidence.
Stronger repository/content, trusted workflow/profile/jobs and resolved environment,
dependency/build proof apply to a reviewed expansion or adoption only when the
compatible collector supports them. Run missing adopted coverage. An open
Approved source supplies proof only through actual compatible approval/content
validation. Never bypass a merged-PR-only collector. Keep independent composition
review and actual stage/delivery freshness; skipped/cancelled results are not tests.

Reviewers add checks for findings, missing scope or unresolved concerns. A changed
input invalidates its dependent evidence; current admission is still checked before
merge. Retry supported failed jobs of an unchanged candidate rather than passing
ones without cause. Diagnose recurring infrastructure/test failures.

For authorized upgrades, record one dependency plan: reviewed engine, Master/skill,
consumer under old rules, compatible service/writers, idle migration and verified
resume. Reuse unchanged facts; refresh changed ones. Native protection, source,
standard release and activation remain distinct; structural CI is not readiness.

Use a durable no-new-start gate only when all actual writers support it. Read the
exact pinned Tracker `docs/MAINTENANCE_AND_CI_EVIDENCE.md` when TT-107 support is
adopted. Publish compatible admission/projection writers before reserving through
`maintenance`; retain its real owner/private claim and use supported drain,
migration and recovery. Reservation and actual idleness are separate. Migration
under a held interval needs the real Maintainer credentials and retains the gate;
resume opens admission without approving or completing tasks. Never invent
commands or flags old clients ignore. Until compatible writers exist, coordinate
one explicit cutover interval with current owner stop/handoff
procedures and the actual idle/CAS migration guard. Do not repeatedly ask about
the same unchanged pause. A genuine new launch, changed coordination or unresolved
owner needs renewed coordination; elapsed time or human confirmation cannot
reserve state. Continue independent preparation while draining; preserve history.

TT-107 native CI coverage is optional and advisory. Its policy must be explicitly
reviewed on consumer current main; exports do not inherit it. First support is
static JSON-formatted Actions workflows, immutable container/userland,
host-independent jobs, exact toolchains and Git-bound inputs, native successful
attempt/step provenance and explicit evidence lifetime. V1 binds only the actual
self-contained producer bytes from the pinned engine with its exact isolated
`python3 -I PATH ...` command; wrappers/arbitrary imports need a separately
reviewed protocol. In separated projects use the direct
`.workflow/tools/tracker_ci_evidence.py` from the project root.

The maintained collector validates actual tested content and current source/batch
approval context. Commit metadata mode remains conservative; tree mode requires
review excluding metadata-sensitive behavior. Coverage names genuine covered
run/job IDs and every missing job; consumer CI runs missing coverage and retains
its required names. Unsupported dynamic workflows/platforms/mutable inputs,
missing or expired proof need fresh jobs. Manual/release/promotion/runtime contexts
retain full/fresh gates. No package/artifact or runtime acceptance is inferred.
This support neither opts in product CI nor changes old project collectors.

New common guidance travels with a reviewed standard upgrade; product tests,
installer internals and runtime safeguards stay local. Keep private claims/sessions
out of public evidence. Report implemented common changes, required Tracker support
and consumers awaiting adoption, without claiming unmeasured savings.
